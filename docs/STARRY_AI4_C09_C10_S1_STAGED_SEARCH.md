- QA_CHINESE_SEARCH_ENABLED、QA_CHINESE_SEARCH_WRITE_ENABLED 預設皆為關閉；未設定為 true 時沿用原問答及 R2 流程。

## C09：純中文搜尋
- 新增 worker/qaTranscriptSearchIndex.ts：依時間與原字幕編號切分約 450–550 漢字的段落；保存 track、講者、字幕範圍與版本。
- SQLite FTS5 unicode61 搭配應用層重疊中文二字詞，支援「感恩」等兩字查詢；參數化 SQL。
- 使用版本指標 qa_search_state，新段落寫入完成後再切換；來源時間戳與 R2 key 不一致即不使用索引。錯誤不能造成逐字稿轉錄失敗。
- 現有故事講者人工歸屬流程優先於普通索引，未核准多人內容不可因新搜尋曝露。

## C10：D1 優先、必要 R2 後備
- 會員授權、獎銜、音檔解鎖檢查在查詢索引前完成，索引只使用允許的音檔 ID。
- 已覆蓋音檔的 QA 問答直接使用 D1 段落：一般查詢 0 次逐字稿 R2 讀取。
- 部分索引可用時，未覆蓋音檔最多讀 2 份 R2 安全回退；索引完全未建立時維持舊版行為。
- 原有 AI 模型、三層回答規則、額度與電池扣費流程不動。

## 驗證

## 2026-10-20 中央AI2 審核意見補強（S1 第二輪）

### 30 題跨音檔檢索
- 30 份不同內容的模擬逐字稿，所有問題每次對整個 30 篇語料庫搜尋，要求正確來源進入前 5 名。
- 另測二字詞、長句、干擾內容、否定問句誤配、私人權限、講者與字幕來源；不能宣稱模擬結果等於實際 112 篇的準確率。

### 訂正、撤銷、刪除、權限同步
- migration 新增 D1 交易內觸發器：新訂正、接受、補充、撤銷及舊版訂正立即使衍生索引無效；不改動原 R2。
- 讀取已失效的索引或舊 R2 原文皆禁止；條件開啟後背景重建只讀必要 R2，套用有效訂正，再切換新版本。
- 每筆資料的 changeRevision 保證並行修訂不會被舊的重建覆蓋。
- track 會員級別、隱私、解鎖及講者資訊改變會立即停用舊索引；查詢仍使用既有當下權限驗證。
- track 刪除時原交易同步清理搜尋衍生資料。R2 原始逐字稿不由本功能刪除。
- SQL 依賴既有 tracks、transcript_index、transcript_correction_events、transcript_corrections；正式 migration 仍未執行。

### D1 儲存與效能驗證（本地模擬；不是正式 Cloudflare 用量）

## 第四輪複審｜2026-10-20 搜尋與訂正同時發生的安全防護
- 中央AI2 指出的競態已針對 SQL 修補：最終 FTS 查詢**同一句 SQL** JOIN `qa_search_state`、`transcript_index`、`tracks`，同時確認 `invalidated=0`、已啟用段落版本、來源 R2 key、來源更新版本和 ready 狀態，避免使用前段檢查後被訂正的舊字幕。
- 最後查詢返回每個引用音檔的「索引代號／修改序號／來源代號與時間」，交給 QA 作**第二次出結果前檢查**。AI 模型可能執行數秒，因此正式留言的 `INSERT ... SELECT ... WHERE EXISTS(...)` 再以**同一筆資料庫寫入操作**原子確認所有引用音檔仍是相同有效來源，失效則拒絕發布並沿用電池退款流程。
- 新增 `tests/c09SearchRaceGuard.test.ts`，在查詢的**前後兩階段之間**刻意插入核准訂正、撤銷、音檔刪除、會員權限變更、R2 key/版本替換；同時測試最終查詢與回傳間的修改，以及 AI 生成後、留言寫入前修改，要求舊內容與留言都不得發布。
