# 繁星回聲架構與 Cloudflare 用量健檢（v133）

基準：正式 main fc64fa8eaa945d102e9cc379e87b557bc5053c71。此版聚焦可量測的貼紙讀取與靜態程式檔請求；保留 React、Workers、D1、R2、KV 架構。

## 實際耗用原因

2026-10-08 檢查 Cloudflare echoes_db「過去 24 小時」：
- 約 75.35k 次 SQL 查詢、2.03M 列讀取、2.46k 列寫入。
- 貼紙 summary 的帳本加總執行 5,959 次、讀取 1.18M 列，約占上述列讀取 58%；每次平均 198 列。
- 初始貼紙識別查詢執行 21,913 次、讀取 21.91k 列。
- 舊播放身份回填查詢執行 129 次、讀取 272.32k 列，屬下一階段改善重點。
- 這是滾動 24 小時的觀測，不等於 Cloudflare UTC 當天剩餘額度。

D1 沒有資料傳輸頻寬費；貼紙造成的主要壓力是 Workers 請求與 D1 掃描列數。
官方：https://developers.cloudflare.com/d1/platform/pricing/

## 此版已完成

1. 可見頁面餘額核對間隔 15 秒改為 60 秒；單一分頁閒置時由 240 次/小時降到 60 次/小時。這項背景請求減少 75%，不代表全站所有流量下降 75%。
2. 登入後才輪詢；回到可見頁面或視窗取得焦點時重新核對。貼紙操作維持立即更新，其他裝置發放在可見頁面最晚下一次分鐘核對時顯示。
3. 同時查詢共用請求，短期回應合併；請求途中若又有貼紙操作，保留一次後續核對與所有異動提示。帳號切換清除摘要快取。
4. 餘額 cursor 未變時，使用索引讀取最新交易位置，跳過 SUM、已解鎖與心得獎勵清單掃描。未讀通知、角色與登入有效性仍向後端核對。
5. 個人紀錄、人工發放紀錄各頁 50 筆，以 createdAt + id 穩定游標分頁；明細及來源連結完整保留，不刪除任何帳本資料。
6. 貼紙簿沿用首頁摘要；下線與人工發放紀錄只於人工分頁載入，規則只於其他規則分頁載入。首次讀取有進行中的相同 GET 時共用請求。
7. 個人紀錄短期記憶體快取 30 秒，餘額 cursor 改變即失效；按「載入更多」可以查所有歷史。快取依會員隔離、最多 8 組，不加入 KV 寫入。
8. 補發復原每位會員同一頁面工作階段最多每 5 分鐘檢查一次；播放完成、心得等正常發放路徑未延後。復原失敗下次重開重試；真的補發才更新紀錄與摘要。
9. 排除偏好、規則、未完聽進度等不相關異動造成的餘額查詢；完聽仍由原事件更新。未來新貼紙行為應發出 echostars:sticker-changed，或由後端回傳 X-Echostars-Sticker-Changed: 1。
10. 新增查詢必要索引；新的紀錄索引完整涵蓋舊 createdAt 索引，因此移除舊索引，降低重複寫入。人工紀錄與未讀通知使用局部索引。
11. Service Worker 對 /assets/ 下含內容雜湊的檔案先讀目前版本的本機快取；HTML 仍網路優先，API 不快取，分享頁不覆寫首頁。
12. 網站版本紀錄更新 v4.7，PWA shell 更新 v133。

## 已量測與驗證

本機用正式 v132 元件與此次元件、相同模擬資料做前後對照：
- 超級管理員首次開啟：9 次 API → 3 次（summary、reconcile、history）。
- 短時間重開：紀錄與補發 API 各新增 0 次；摘要是否發出請求取決於距上次核對的時間。
- 若確實發生補發或外部新交易，會再核對，請求數不保證固定 3 次。
- 手機 390×844、桌機 1280×900：分頁、延後管理讀取、重開、無橫向溢位與頁面錯誤均通過。
- SQLite 回歸：同時間交易、分頁期間新增交易、所有 126 筆歷史可完整讀取且無重複，其他會員資料不會混入。
- 餘額未變時至多 4 條 SQL（已完成此 Worker 實例的 schema 初始化）；沒有 SUM 或解鎖清單查詢。索引查詢計畫沒有臨時排序。
- 保留並回歸測試普通會員完聽補發、發放上限、並行解鎖不透支、人工加貼紙重試不重複、VIP、Google session 與 blocked user 驗證。
- 完整 323 項回歸、TypeScript、正式 build 通過。
- 真實全站節省比例需部署後以相同時段與使用量觀察至少 24 小時，不能用本機數字直接宣稱正式費用下降比例。

## 後續建議與取捨

### 優先 1：觀察部署後的 D1 統計
比較相同使用量下的 summary 查詢次數、SUM 掃描列、Workers 請求與錯誤率。Workers Free 每日 100,000 次請求、D1 每日 5M 列讀取與 100k 列寫入；免費額度於 UTC 00:00 重設。不要用 SQL 查詢數當成 Workers 請求數。
來源：https://developers.cloudflare.com/workers/platform/pricing/
來源：https://developers.cloudflare.com/d1/platform/pricing/

### 優先 2：把舊資料回填改為有版本記錄的一次性 migration
目前多個 Router 使用每個資料庫 binding 的 WeakMap 記憶體初始化；冷啟動或 binding 換物件後仍可能再次執行歷史回填。播放身份回填的 272k 掃描列尤其值得處理。改版需驗證舊資料與新會員路徑，讓 migration 完成後只讀版本標記，不重掃全部會員。不能只刪回填邏輯，否則舊帳號會失去進度關聯。

### 優先 3：會員餘額彙總表
若會員交易長期增長，新增 D1 餘額彙總表，讓新增交易與餘額更新在同一原子交易／trigger 中完成。歷史帳本仍為稽核依據；首次 backfill 與併發更新需避免重複計入、透支或兩份餘額不一致。此版先減少沒異動的 SUM；真正花費與發放的安全檢查仍使用既有原子邏輯。

### 優先 4：逐步收回全域 DOM / fetch 補丁到 React
App.tsx 約 3,200 行；目前 src 仍有 9 處 MutationObserver，且數個政策會包裝全域 fetch。Google、媒體與教學觀察器各有功能，不能把「有觀察器」當作沒用就刪除。分功能搬到 hooks／正式元件，搭配互動回歸，避免一次重寫登入與權限。

### 靜態資源、KV 與私有資料
目前 run_worker_first = ["/*"] 保留爬蟲／隱私保護；不能直接跳過所有靜態資源 Worker 而丟失該政策。此版優先使用本機快取。貼紙餘額不能只保存在 localStorage，也不適合每次異動寫 KV：需跨裝置一致、防修改、可稽核。公開規則可再做有版本的短期快取；私人紀錄不得共用 CDN 快取。
索引會增加寫入列，應只保留查詢需要的索引：
